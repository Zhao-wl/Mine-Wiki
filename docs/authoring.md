# 内容维护约定

一个节点对应一个能完整学懂的目标。它可以包含多个紧密关联的概念；例如“逆、核、秩、行列式”共同解释信息为什么不能唯一恢复。不要按公式或段落数量拆文件。

## 三种入口，一个正文源

- 节点 `content/nodes/<id>.json`：学习目标、直觉与解释、逐步例证、理解检查与答案；公式、图解、交互实验和共享数值算例引用按内容需要提供。
- 路径 `content/paths/<id>.json`：真实问题、学习目标、引用节点的 `steps`、步骤过渡与应用边界。不要复制节点正文。
- 主题 `content/topics.json`：引用 `nodes` 和 `paths`，同一节点可以属于多个主题。

生成器将节点正文分别放入独立页面和连续路径。两者是同一源的生成结果，不是两份作者维护的内容。旧 `lessons/zero-scale/course.json`、Markdown 及同目录公共脚本副本也是兼容产物，不要直接编辑。

## 稳定 ID 与引用

ID 使用小写英文和连字符，第一次确定后长期保留，不随标题、主题或顺序改名。文件名与 ID 相同。对外节点地址为 `knowledge/<id>/index.html`；主题变化不会改变它。

```json
{
  "id": "basis-coordinates",
  "status": "ready",
  "requires": [
    {"node": "point-vector", "reason": "先区分位置与位移，才能理解坐标描述的是哪个对象。"}
  ],
  "related": [
    {"node": "invertibility-information", "anchor": "example"}
  ]
}
```

`requires` 表示必要前置，有方向且必须写理由；不能自引用或构成循环。`related` 表示可选延伸，按双向关系展示，不当作前置。可选 `context` 使用相同的 node/anchor/reason 引用形状，必须写理由：它是有方向的语境关联，不加入先修图、不自动建立反向 related；允许相互提供语境。反向“哪些知识以此为前提”、主题归属与路径使用关系由生成器计算，不手工维护两份关系。

稳定块锚点包括 `overview`、`intuition`、`formula`、`example`、`experiment`、`exercise`、`boundaries`、`cases`、`connections`、`notes`、`references`；只有存在相应内容的锚点才能被引用。元数据使用 `node`/`anchor`，由生成器解析链接，不硬写跨目录路径。资料使用 `sources` ID，API 陈述保留具体版本和实测边界。

若未来需要拆一个节点，保留原 ID 作为完整总览，再增加新节点并链接过去；不要让旧 ID 静默变成另一个含义，也不要复用已用过的 ID。重大教学变更在 Git 记录，读者的自评不会被当作自动重新考试的结果。

## 缺失节点与完成状态

- `stub`：只有范围与补充意图也可以，但必须有 ID、标题、摘要、`requires` 和 `related`。页面明确显示“待补充”，不能勾选已掌握。
- `draft`：正在整理，可展示已有内容，但不标为完整教学单元。
- `ready`：标题和摘要（`title` / `summary`）交代学习目标；`intuition` 提供直觉与解释；`steps` 给出可跟随的例证、推演或操作过程；`exercise` / `answer` 检查理解并说明理由；保留阅读时长。采用外部事实、观点或规范时填写必要的 `sources` 引用，原创解释可不引用外部资料。状态是作者声明，自动检查不代替教学质量和来源充分性的判断。

`formula`、`lab`、`example`（共享数值算例 ID）都可省略；不要求非数学节点编造公式或数值例子。`steps` 是一般例证，不等同于共享数值算例引用。提供这些可选字段时仍会校验其内容或目标；没有公式就没有 `formula` 锚点，引用该锚点会报错。现有九个数学节点的公式与共享算例继续保留。

可以引用已登记的 stub；拼错 ID 或未登记目标始终报错。ready 路径要求所有步骤 ready，并且每个必要前置在更早步骤中出现；不能把缺失前置悄悄跳过。draft 路径允许未完成步骤，页面显式提示。单节点的内容可以 ready，但若其前置未 ready，会显示“前置待补齐”。

引用、锚点、状态、必需字段、前置循环、路径顺序、来源与本地资源均有检查。未知关系不能当作可学习节点蒙混通过。当前没有为将来可能出现的法线问题预建课程或空壳主题。

## 增量修改

1. 描述新问题及希望读者能解释或算出的结果。
2. 在 `content/nodes` 查找可复用单元，沿 `requires` 检查前置是否齐备。
3. 缺口先登记范围；补齐完整解释、例证与理解检查后再置为 ready。已有内容修正只改对应节点。
4. 新建或调整问题路径的 steps 与过渡；主题仅新增引用。稳定数学结论与特定引擎版本依据分开。
5. 执行生成、内容/引用校验；数学或实验改变时运行对应测试。检查受影响节点和路径的手机布局、键盘操作和静态后备。
6. 本地核对后，再按当次授权决定是否提交、推送或部署。构建脚本没有任何发布动作。

当前规模全量生成即可，不做增量构建缓存、数据库、实时 AI、知识图谱服务或自动资料抓取。

## 交互与共享资源

数学实现以 `assets/math.js` 为准；实验 HTML 位于 `assets/labs.html`，按 `lab` ID 引用。`assets/app.js` 只初始化页面上存在的实验。每个页面一个实验 ID 最多出现一次；想在同一连续路径复用同一实验，应复用其完整学习单元，避免 DOM ID 冲突。不要为此提前建立复杂组件框架。

共享例子位于 `content/examples/zero-scale.json`；节点页面展示自己的算例约定，路径只需在开头展示。新增不同例子时要同步检验公式、图解和实验的数值一致性。二维列向量、x 右 y 上、右侧先执行，以及精确零不替换 epsilon 的约定继续保留。

## 兼容与本地记录

`lessons/zero-scale/index.html` 仍是原问题入口。旧章节锚点 `points/basis/columns/order/affine/hierarchy/inverse/precision/reparent`、实验锚点以及 `api/video/notes/references` 全部保留。`#video` 指向折叠的历史资料入口；视频不再嵌入默认学习页面。历史媒体文件不变。

旧 `mine-wiki.zero-scale.v1` 通过路径元数据的一一映射迁入 `mine-wiki.learning.v1`：掌握度按稳定节点 ID 共享，疑问归入 `path:zero-scale`，节点疑问使用 `node:<id>`。迁移只填补新记录没有的字段，不覆盖明确的 false 或新疑问，保留原始旧键。清除新记录中的当前页面内容不会触发再次导入。

格式异常、版本过新或存储不可用时不覆盖原记录，页面提示并允许临时编辑与导出。导出包含全部节点自评、各页面疑问和迁移标记；当前不提供自动导入或跨设备同步。浏览器域名/端口变化意味着不同存储来源，发布后也不会自动获得本机预览时的记录。

## 审美内容的兼容扩展

不改旧节点的必需字段。新节点可提供 `question`（问题字符串）、`boundaries`（非空字符串数组）与 `cases`（案例数组）。每个案例包含 `title`、`paragraphs` 和 `sources`；案例来源必须也登记在节点 sources 中。问题、原理、逐步例证、实验、案例、练习及来源均从节点进入单页和路径；`boundaries` / `cases` 只在存在正文时产生可引用锚点。读者看到的资料事实、本课解释与待核实问题应明确区分。

非数学路径可以省略 `example`，不需要为此编造共享数值算例或数学先修。原 `zero-scale` 的算例、媒体、迁移映射和导出继续保留。外部案例本次只链接出处，不嵌入外部图片；实验 SVG 为仓库原创。来源说明记录新资料的核查日期，不重写旧来源的历史核查日期。

主题可选 `learning_map`：`orientation`、三层 `layers`、建议节奏 `stages` 与 `history_questions`。layers 和 stages 的每个组都有稳定 ID、title、summary、nodes；stage 另有 practice。两组分别完整覆盖该主题节点，不能重复、遗漏或引用主题外节点。地图的完成数量和标签从节点 status 计算，不在正文中手工维护两份状态。阶段是建议顺序，只有 requires 才是必要先修。

共享实验模板仍在 `assets/labs.html`，审美增强单独放在 `assets/aesthetics.js`，仅含该实验的页面加载。没有新框架、平台、音视频或远程运行依赖。练习字段 13 个、自检项 4 个，专用键 `mine-wiki.aesthetics.observation.v1`；只有主动保存才写入。节点页和首课路径共享这份练习，版本或格式不兼容时不覆盖原值；保存失败仍能导出当前页。返回初看保留文字；重置仅清当前页面、保留已保存副本；删除按钮仅移除专用键、保留当前文字和其他课程记录。全站自评/疑问仍由既有 app.js 管理。

新增检查：`python3 tests/aesthetics_content_test.py` 和 `python3 tests/aesthetics_browser_test.py`。原浏览器测试可用 `MINE_WIKI_BROWSER_OUT=/tmp/mine-wiki-zero-regression` 分开保存截图与结果，避免重写历史验证资产。离线读者包同步包含审美脚本。
